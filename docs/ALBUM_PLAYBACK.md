# AI 相框播放规则

真人播放器以动作帧表的起始帧（露米源第 0 帧，小桃源第 25 帧）作为静图。等待、聆听和加载回复时不播放预览动作。动漫播放器不受此规则影响。

露米使用前 25 帧及其倒序，共 50 帧、2 秒的小幅循环。小桃使用睁眼的第 25–49 帧以原速往返，连续三个两秒周期后正向播放一次眨眼（第 0–25 帧），再回到睁眼片段收尾；持续说话约每八秒眨眼一次，不倒放眨眼。眨眼开头从第 25 帧切至第 0 帧，再正向播放回第 25 帧；两帧均为接近的睁眼姿态。眨眼与睁眼片段为直接切换，使用接近的姿态，仍需真人观感验收。短回复可能不触发眨眼。两者共用 public/album-motion-plan.json 帧表，前端只收尾当前两秒周期，不等待整个八秒序列。帧、裁剪、关键点、矩阵和遮罩使用相同排列。渲染缓存版本已升级，旧的长动作视频不复用。

本阶段实时回答固定使用 idle，暂不自动插入微笑和点头；现有长动作不可当作已验收短动作。微笑、点头需要准备短素材后再接入。

父页面到真人 iframe 的播放消息新增可选 motionEndFrame，由渲染结果 metrics.nextSourceFrameOffset 提供，含义为当前片段结束后动作循环的下一帧。旧消息缺失时回静图，不猜测动作相位。

音频真正播放结束后，播放器显示无口型的源动作剩余帧，完成当前周期后暂停在各自的起始帧。长的剩余周期加速收尾，计划时长不超过 1 秒，实际还受浏览器 seek 耗时影响。句间缺流回静图。新片段或打断取消旧收尾，防止旧异步回调隐藏新回答。

验证：node --test test/album-motion.test.mjs；离线样片：.venv-dh-live/bin/python -B scripts/verify_album_motion.py。任意照片上传、端到端语音延迟及浏览器中的收尾观感需单独验收。

## 页面模式与控制区

每次打开页面默认聊天模式。聊天模式的切换按钮与人物设置、字幕、清空对话、动作测试归入右侧现有控制区，不占页面顶部独立一条。

相框模式完整显示真人源视频（`object-fit: contain`，按比例留边，不额外裁切），右侧独立栏放置模式切换、人物设置、清空对话、语音按钮和状态提示。人物设置在两种模式均可打开，真人/动漫、角色与造型选项统一归入设置面板。相框模式收起聊天记录、文字输入、字幕按钮和动作测试入口；切回聊天恢复原有显示状态。

`public/view-mode.js` 只切换布局并同步同源 iframe 的显示属性，不重载人物、不重建通话、不自动申请麦克风。iframe 更换角色后通过 load 事件恢复相框显示属性。两种页面模式共用本篇的真人动作规则。

## 验证与局限

已验证桌面和手机布局、模式来回切换保留同一 iframe/语音按钮、相框设置切换小桃、刷新默认聊天。真人播放验证包含整段、连续分段、PCM/fMP4、回答接续取消收尾和打断恢复静图；单元测试覆盖小桃全部 200 个相位仅收尾当前两秒周期。

源素材本身只拍到的范围无法通过 contain 补全。当前实现使用已有预处理素材，尚不包含任意照片上传生成动作。离线验证生成的音视频保存在临时目录，不随源码提交。
