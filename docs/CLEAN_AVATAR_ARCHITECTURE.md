# 自研洁净真人口型架构

## 目标

在不加载、复制或修改 MatesX 预编译 WASM、授权数据包和纹理的前提下，使用项目自己的真人视频和可审查的开源推理代码实现实时语音口型。DH_live 公开 Python 源码和检查点仅用于本地非商业验证；重新分发前必须独立核对代码、权重和训练数据条款。

## 洁净室边界

- 只借鉴“视频逐帧定位嘴部、音频驱动口型、动作视频切换”这一通用流程。
- `scripts/prepare_clean_avatar.py` 独立调用 MediaPipe，输出项目自有的 `digitalman-mouth-track` JSON。
- `scripts/build_clean_mouth_atlas.py` 只从项目自己的 MiniMax 视频提取带羽化透明度的嘴形图集。
- `public/clean-avatar/runtime.js` 只使用浏览器原生 Video、Canvas 和 WAV 解析能力。
- `profile=clean` 不请求 `/dh-live/` 下的脚本、WASM、数据包或视频资源。
- 不对 MatesX 水印进行遮挡、擦除或二进制修改；通过完全替换运行链路消除该依赖。

## 性能是硬性验收条件

新链路不以“能离线生成 MP4”为完成标准，而以真实对话的首句延迟和连续性验收：

- 用户说完到人物开口：目标 1.5–2.5 秒，本地渲染不得额外阻塞整句时长；
- 首个可播放口型块：音频到达后不超过 500 ms；
- 稳态推理：必须快于实时，目标 RTF 不高于 0.7；
- 句间不允许回待机、黑帧、重置第一帧或可感知的无声缺口；
- 任意第二轮及以后不得重新加载模型、人脸框、参考帧或角色纹理。

实现约束：

1. Audio2BlendShape、DINet、待机帧、稠密网格和参考张嘴帧在服务启动时一次性预载；
2. TTS 以自然短句或 PCM 分块输入，Audio2BlendShape 保留 LSTM 隐状态，不把每块当作新句子；
3. 渲染器每次处理约 200–400 ms 的帧，生成块与当前播放块双缓冲并行；
4. 浏览器只接收口部 ROI/已编码小帧并与原视频合成，不在服务端为每句重新编码整幅 MP4；
5. 队列落后时优先合并中间帧并保留音频时钟，不允许嘴形逐渐落后声音。

## 数据格式

`digitalman-mouth-track` 每帧只保存以下归一化数据：

- `cx`、`cy`：嘴部中心；
- `width`：嘴角距离；
- `gap`：上下唇距离；
- `angle`：嘴角连线角度；
- `detected`：该帧是否直接检测成功。

`digitalman-mouth-atlas` 保存 5 个由闭嘴到张嘴的 RGBA 嘴形切片、源帧编号、开合比例、显示宽度比例和宽高比。边缘 Alpha 在离线阶段羽化，运行时按当前帧嘴部位置、尺寸和旋转角贴合。

## 实时流程

1. 主页面把 MiniMax TTS 返回的 WAV 通过既有 iframe 消息协议发送给洁净播放器。
2. 播放器按 RIFF chunk 查找真正的 `data` 区，不假设固定 44 字节 WAV 头。
3. 每 18 ms 音频窗口计算 RMS，经过起音和收音不同速率的平滑得到开口强度。
4. 开口强度映射到嘴形图集；当前版本限制为较小的前 4 档，不使用最大开口。
5. 嘴形按当前视频帧的中心、宽度和角度融合；停止语音后恢复原视频嘴部。

## 依赖与素材来源

- MediaPipe：仅用于离线人脸关键点检测，应保留其 Apache-2.0 许可证记录。
- OpenCV：仅用于离线读取视频、裁剪和生成 PNG，应保留其 Apache-2.0 许可证记录。
- 浏览器运行时：项目原创 JavaScript，不包含第三方推理二进制。
- 人物视频与嘴形图集：来自本项目中用户选择并由 MiniMax 生成的测试素材；商用前仍需确认原始图片和生成服务条款。

## 当前限制

- 第一版按音量选择嘴形，还没有区分 `a/i/u/e/o` 等音素。
- 图集来自同一人物的一段张嘴视频，适用于该人物；更换角色需要重新生成轨迹和图集。
- 大角度侧脸、手遮嘴和快速转头尚未支持。
- 后续可增加中文音素到 8–12 个 viseme 的映射及共发音平滑，不需要改变动作和主页面协议。

上述图集版已证明只有音量分档，不能达到真人口型要求，仅保留为失败对照。连续 Audio2BlendShape 和 DINet 神经局部融合现已在 `?profile=dinet` 中验证，模型常驻后的整句生成 RTF 约为 0.33–0.35；下一阶段是把整句 MP4 改为首段可立即播放的流式容器，不再扩展图集档位。
